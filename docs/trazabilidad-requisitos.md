Estados: **Verificado** = implementación y evidencia reproducible del requisito completo; **Parcial** = implementación o cobertura incompleta; **Pendiente** = no se localizó implementación funcional del comportamiento exigido en el alcance revisado; **Sin evidencia** = implementación identificada, pero no evidencia suficiente para confirmar el cumplimiento completo. «Pendiente» es el diagnóstico de esta versión, no una afirmación sobre trabajo en ramas ajenas no revisadas.

La columna «Previo» conserva el diagnóstico de S2. «Actual» no es el estado de una tarjeta de Trello: se asigna por cumplimiento del requisito. No se deriva un porcentaje global ni se extrapolan pruebas con mocks a funcionamiento real de servicios externos.

Consultas locales de lectura realizadas con `urllib.request.urlopen` y `json.load` a `http://127.0.0.1:8000`: `/` 200; `/api/publicaciones/` 200, diez elementos; `/api/localidades/capital/publicaciones/` 200, cero elementos. Para reproducir el resultado de QA-01 en la versión revisada: `node --test app/core/test_auth_flow.js`. Su ejecución de 4/4 aprobadas es evidencia de la tarea anterior, no una segunda ejecución dentro de DOC-01. Para repetir backend, el comando documentado es `docker compose exec web python manage.py test core`, **sólo en un entorno de pruebas PostgreSQL autorizado y aislado**, nunca sobre una base compartida con datos de trabajo. No se ejecutó la suite Python completa ni llamadas reales a IA/ingesta durante DOC-01. Las pruebas identificadas en la matriz son evidencia de cobertura existente, no resultados actuales atribuidos a esa suite.
